# Security

A personal project with no user accounts and no server-side data: the app itself is a
static site holding one person's D&D session state in the browser. The things worth
protecting are the source, the build pipeline, and the accounts/tokens that can change
either.

## Threat model

**Assets:** the source on `main` (what gets deployed), the CI pipeline (what deploys
it), and the tokens that can push code, deploy, or reach Trello.

| Entry point                                                            | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| npm packages (supply chain)                                            | `package-lock.json` committed, `npm ci` everywhere (no arbitrary installs); `npm audit --audit-level=high` in CI; GitHub Dependabot alerts and CodeQL (JS/TS + Actions) enabled.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| PR and Trello card text (untrusted input read by CI/agents)            | Never interpolated into a shell string — passed through `env:` (`trello-comment.mjs`, `pr-title.yml`). `review.yml` always checks out `main`, never a PR's own branch, so a PR can't edit its own rules or get its code checked out in a workflow that holds secrets; it treats `gh pr diff` output as code to review, not instructions, and is advisory-only (no write/approve access). `.claude/hooks/guard-trello.sh` forces a confirmation on every Trello write except a card move, so a card's own text can't get itself edited unattended. `review.yml` sets `allowed_bots: claude` (naming only that App, not `'*'`) so it also runs on `build.yml`'s own bot-authored PRs, without opening the trigger to other Apps' events on this public repo.                                                                                                                                                                                                                                                                                                                                                                                                                        |
| CI (`.github/workflows/`)                                              | Third-party actions pinned to commit SHAs; `permissions:` set to the minimum each job needs (most are `contents: read` or less); secrets are unavailable to PRs from forks (the `preview` job's `if`); `main` is protected by a ruleset requiring the `check` and `pr-title` status checks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Fork PRs skip Lighthouse and bundle-size comparison                    | The `preview` job — Lighthouse CI and the bundle-size comparison against main — doesn't run for PRs from forks (no secrets), and GitHub counts a skipped check as passing, not blocking. The bundle-size _budget_ still runs for every PR in `check`, which has no such `if`; only the Lighthouse budgets and the size-change comparison ride along with `preview`. Accepted risk for now — this is a personal project with no fork contributors expected.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Cloud sessions (Claude Code on the web)                                | Hold no Trello or Firebase secrets (only CI does); GitHub access goes through the Claude GitHub App's proxy, scoped to this repo; `scripts/setup.sh` is the only thing the `SessionStart` hook runs automatically. The Trello permission rules and `guard-trello.sh` are listed under the cloud connector's tool names (`mcp__Trello__*`) as well as the local ones, so card writes ask in both.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `build.yml` (unattended agent, scheduled and manually dispatched)      | A fourth agent environment, with no human present to answer an interactive prompt: `fetch-card` is the only job holding Trello secrets; it only writes a Trello comment when a card has failed its retry cap, and only reads otherwise (a card not sitting in Up Next and fully templated is refused, on both the manual and scheduled paths). It reads GitHub's live pull list (`pull-requests: read`) to skip cards that already have a PR, never GitHub's search index. `build` holds `CLAUDE_CODE_OAUTH_TOKEN` and no Trello or Firebase secret, and its `--allowedTools` list has no `ask`-tier entries, so anything outside it is denied outright instead of hanging; its prompt also tells the agent not to retry a denied call. A `verify-pr-opened.mjs` step fails the job if the Claude step reported success but left no PR behind, and a separate `flag-no-pr` job (holding Trello secrets, like `fetch-card`) comments on the card when that happens — `build` itself still never touches Trello. The `BUILD_PAUSED` repo variable is a kill switch for the schedule. Same hardening as `review.yml`: actions pinned to commit SHAs, `permissions:` minimal per job. |
| `triage.yml` (unattended agent, drafts cards from untrusted wish text) | Reads the most directly untrusted input of any pipeline here — raw wish text and replies from anyone who emails the Requests address, with no review before the agent sees it. `fetch-requests` is the only job holding Trello secrets, same split as `build.yml`. `draft` (the agent, Haiku, 20-turn cap) holds no Trello or repo secret and has no Trello, Bash, or repo-checkout tool at all — only `Read`/`Write` on the working directory, so it can at most read/write its own two JSON files. It's told to treat wish text and comments as data, never instructions, no matter what they say. The actual write-scope enforcement is code, not agent discipline: `apply` (holding Trello secrets again, no model) runs every drafted entry through `triage-validate.mjs`, which rejects any entry naming a card id `fetch-requests` didn't hand over, and only ever calls the two endpoints (card update, add comment) `trello-apply-drafts.mjs` contains — it can't move, archive, or label a card because no such call exists in that script. The `TRIAGE_PAUSED` repo variable is a kill switch for the schedule. Same hardening as `build.yml`.                         |
| Local agent shell/tool use                                             | `.claude/settings.json` denies reading `.env*` files and requires confirmation for anything outside its allowlist; `.claude/hooks/guard-bash.sh` blocks force-push and `rm -rf`/`.git` deletion regardless of permission mode.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Hosting (Firebase)                                                     | CSP, `X-Content-Type-Options`, and `Referrer-Policy` set in `firebase.json`; HSTS is sent unconditionally by Firebase Hosting itself. `e2e/security-headers.spec.ts` checks all four are present on the preview and that the app still renders under the CSP.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Tokens (see inventory below)                                           | Scoped as narrowly as each provider allows; stored only as GitHub Actions secrets, never in the repo.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

## GitHub security features

Secret scanning (with push protection), Dependabot alerts, and CodeQL default setup
(JavaScript/TypeScript + GitHub Actions) are all on for this repo — free for a public
repo. Check `Settings → Code security` to confirm they're still enabled.

| -------------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `FIREBASE_SERVICE_ACCOUNT_DND_TRACKER_2C66F` | GitHub Actions secret                | Deploy to this Firebase Hosting project only                                                                           | Delete the service account (or its key) in Google Cloud Console → IAM, then re-run `firebase init hosting:github` |
| `TRELLO_API_KEY` / `TRELLO_TOKEN`            | GitHub Actions secrets               | Read/write access to **all** boards on the Trello account (Trello tokens aren't board-scoped) — a known, accepted risk | Trello → Settings → Applications, or revoke at trello.com/app-key; then set new secrets                           |
| `CLAUDE_CODE_OAUTH_TOKEN`                    | GitHub Actions secret                | Run Claude Code in Actions (`review.yml`, `build.yml`, `triage.yml`), billed to this account's plan                    | Anthropic Console → revoke the token, then `gh secret set` a new one                                              |
| Trello connector OAuth (used by `/card`)     | Claude.ai account, not a repo secret | Same all-boards read/write reach as the CI token, from any Claude Code session                                         | Trello → Settings → Applications → revoke "Claude"                                                                |
| `GITHUB_TOKEN`                               | Auto-issued per workflow run         | Whatever that job's `permissions:` block grants; expires when the run ends                                             | Nothing to revoke — scope is fixed in the workflow file                                                           |

## Out of scope

- Firestore and Firebase Auth security rules — they arrive with sync, not before.
- Penetration testing.
